# 图片不满意时的修改功能

## 1. 先判断：重新生成还是修改原图

两种操作解决的问题不同：

| 画面问题 | 推荐操作 | 原因 |
| --- | --- | --- |
| 整体构图、人物、机位或场景全错 | 修改提示词后重新生成 | 原图没有值得保留的结构 |
| 脸太老、不够好看、有胡子、眼睛异常 | 修改现有图片 | 保留人物、服装和背景，只修脸部 |
| 手指、肢体、衣服或局部背景错误 | 修改现有图片 | 局部修复比整张重抽更稳定 |
| 想把近景改成全景或完全改变姿势 | 较大调整，必要时重新生成 | 改动会触及整张构图，身份漂移风险更高 |
| 同一镜头只想比较不同模型 | 重新生成多个模型候选 | 适合寻找完全不同的视觉方案 |

“修改现有图片”调用服务器上的 `FLUX.1 Kontext Dev FP8`。它读取当前图片并按
编辑指令修改，不是把原提示词原样再抽一次。

## 2. 界面操作

### 角色定妆

1. 打开“角色定妆”。
2. 找到要修改的候选图，点击“不满意 · 修改此图”。
3. 选择常见问题，继续补充准确要求。
4. 检查目标提示词和排除项，选择保留程度、候选数和 Seed。
5. 等待进度条完成，比较候选。
6. 点击“使用这张”才会把它设为当前定妆照；也可以只保存候选。

### 分镜首帧

1. 打开“分镜脚本”，选择镜头。
2. 点击“不满意 · 修改当前图”。
3. 完成修改后选择一个候选作为当前首帧，或只保存结果。
4. 点击“历史版本”可以查看当前图和以往候选，并随时切回。

当前首帧切换后，图片质检状态会自动回到“待审核”，防止旧图的通过结论错误地
继承到新图。

## 3. 怎么写修改要求

不要只写“变好看”“修一下”。建议按以下顺序写：

```text
要改什么 + 改成什么 + 必须保留什么 + 绝对不要出现什么
```

例如：

```text
把人物改成十八岁左右的英俊少年，五官精致但自然，面部干净无胡须；
保持同一人物身份、青色服装、发髻、站位、镜头和村落背景不变；
不要成熟大叔感，不要磨皮塑料感，不要改变衣服颜色。
```

排除项可写：

```text
old, middle-aged, beard, moustache, deformed face, extra fingers,
plastic skin, text, watermark
```

提示词越具体，模型越容易知道哪些区域能改、哪些内容必须锁住。

## 4. 保留程度

- **严格保留**：只修改指定问题。适合脸、眼睛、胡子、手指、衣服小错误。
- **平衡修改**：允许相关区域一起调整。适合人物美化、光线、局部构图和背景。
- **较大调整**：允许姿势或构图变化。适合原图问题较多但仍想保留人物身份时。

如果“严格保留”几乎没变化，先改成“平衡修改”；如果仍然失败，再回到原生图
界面重新生成，而不是无限提高修改幅度。

## 5. 候选、版本和保存位置

每次修改会新建独立目录，不覆盖原图：

```text
角色：projects/<项目>/outputs/image_revisions/revision_<时间_编号>/
分镜：projects/<项目>/production/shots/episode_<集号>/revisions/
```

每个修改目录都包含候选 PNG 和 `manifest.json`。清单记录：

- 原图路径和上下文；
- 编辑模型及模型文件；
- 问题、目标提示词、排除项和保留程度；
- Seed、生成日期时间和耗时；
- 所有候选图片。

“使用这张”只是改变当前选择，不会删除其他文件。分镜历史版本会从 Episode JSON
中的 `image_generation.candidates` 读取，因此重新启动应用后仍可查看。

## 6. 常见失败处理

- **按钮不可用**：当前角色或镜头还没有实际图片，先生成或选择首帧。
- **提示需要 GPU 服务器**：Kontext 在远程 3090 上运行；到“连接与设置”填写
  SSH 信息并检测连接。
- **提示模型未就绪**：在设置页点击“安装/修复 FLUX.1 Kontext”，完成后重新检测。
- **人物身份变化**：改用“严格保留”，把“保持同一人物身份、脸型、发型和服装”
  写进修改要求，并减少同时修改的项目。
- **结果变化太小**：改用“平衡修改”，把最重要的变化写在第一句。
- **多次仍不满意**：回到角色或分镜提示词，修正年龄、外貌、服装、镜头、构图和
  负面提示词后重新生成多个模型候选。
