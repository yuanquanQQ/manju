## 本轮目标

解决高动作镜头“起始图僵硬、结束帧变化太小、Wan FLF2V 只产生衣摆晃动”的问题。

## 已确认的问题

- Wan2.2 FLF2V 14B 本身可以稳定保持脸、服装和背景，但动作幅度取决于首尾关键帧。
- FLUX Krea 与 Juggernaut XI 属于普通生图/img2img 模型。提高 denoise 后会换脸、换衣、
  换背景甚至增加道具；降低 denoise 后结束帧又几乎冻结，因此不适合作为动作尾帧编辑器。
- 旧版走路尾帧固定要求“右脚向前”，而第 1 镜头首帧本来就接近右脚在前，导致模型即使
  遵守提示也没有形成可见步态变化。
- 仅按像素 SSIM 选择候选会偏爱几乎不动的图，同时会错误惩罚 Kontext 的真实纹理重绘。

- 精确删除服务器 4 个 H3 专属权重，共释放 42,470,585,471 字节；历史 MP4、清单和可重装脚本保留。
- 安装并检测官方 FLUX.1 Kontext Dev FP8：

  - 共享依赖：`clip_l.safetensors`、`t5xxl_fp8_e4m3fn.safetensors`、`ae.safetensors`
  - ComfyUI 节点：`FluxKontextImageScale`、`ReferenceLatent`、`ConditioningZeroOut`
- 设置页增加 Kontext 独立安装、状态检测和错误提示。
- 自动结束帧固定使用 Kontext，清单记录模型、日期时间、参考图和编辑模式。
- Kontext 输出在保存前强制缩放回视频目标尺寸（当前样例为 832×480）。
- 走路尾帧版本升级到 v5：不再固定左右脚，而是要求交换参考图中的前腿/后腿并完成一步。
- Kontext 使用短编辑指令，把动作变化放在最前，避免人物身份和风格长提示淹没动作。
- 候选筛选升级为“细节 SSIM + 模糊低分辨率构图 SSIM”，并以可见变化与构图稳定之间的目标区间选取。

## 通用图片修改功能

在动作尾帧之外，Kontext 已接入桌面应用，作为角色图和分镜首帧的通用修改器：

- 角色候选图增加“不满意 · 修改此图”；
- 分镜编辑区增加“不满意 · 修改当前图”和“历史版本”；
- 支持常见问题预设、自由修改要求、目标提示词、明确排除项、严格/平衡/较大
  三档保留程度、1～4 个候选和自定义 Seed；
- 保持原图尺寸生成，显示真实进度和耗时；
- 结果弹窗先比较候选，只有点击“使用这张”才切换当前图；
- 分镜修改前会把手工导入的固定首帧归档为不可变历史版本，避免切换时覆盖唯一原图；
- Episode JSON 保存全部候选、模型、时间、Seed、提示词和 Manifest 路径，应用重启后
  仍能查看和恢复；
- 已使用真实 3090 + FLUX.1 Kontext 完成一张 832×480 分镜首帧烟雾测试，约 63.2 秒，
  人物、青色服装、站位和村落背景得到保留；测试候选未替换正式分镜；
- Python 编译、Ruff 和 130 项自动测试全部通过。

使用与故障处理见：`docs/04-图片不满意时的修改功能.md`。

## 不要重复踩的坑

- 不要再用 Krea/Juggernaut 高 denoise 生成动作尾帧。
- 不要把最高 SSIM 当作最佳动作候选；最高分往往意味着动作被冻结。
- 不要在没有检查起始腿位时固定写“左脚/右脚向前”。
- 不要在尾帧未通过实图检查时直接批量运行 14B FLF2V。
- 不要删除用途不确定的模型；本轮只删除了已确认退出当前路由的 4 个 H3 专属文件。
