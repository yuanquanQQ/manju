# 阶段 08：视频生成

## 1. 阶段目标

将审核通过的镜头关键帧转换为短视频片段，在保持人物、场景和构图稳定的前提下实现符合分镜的动作与镜头运动，并输出可供自动剪辑使用的标准化视频。

V1 通过适配器支持一种经过基准验证的本地图生视频引擎；具体模型在实施时根据 RTX 3090 的显存、速度、许可和质量测试确定，不把业务 Schema 绑定到模型名称。

### 当前实施状态（2026-07-27）

- 已实现桌面“视频生成”工作台、首帧绑定、镜头参数编辑、批量进度与播放入口。
- 已实现引擎无关的 `VideoRenderSpec`、标准 MP4/Manifest、SQLite Job 和 Artifact 登记。
- 已实现本机 FFmpeg 漫画动效 Profile，可生成推近、平移、摇镜和稳定静帧，
  并可将标准镜头串联合成为整集无声预览。
- 已将人物动作、环境运动、连续性限制、负面提示词、动作幅度和运动方向拆为独立字段；
  旧项目中的 `motion_prompt` 会自动兼容到人物动作。
- 已实现可选结束帧、首尾帧 Profile 校验、候选数量、切换余量和逐镜头引擎选择界面。
- 已接入 MiniMax H3 FL2VA 本地引擎（`minimax_h3_fl2va`）和原生音频；未实现的
  Profile 会明确阻止提交，不会静默冒充 AI 视频。
- 已实现 H3 的 ComfyUI 工作流（`MiniMaxH3ImageToVideo`、`VAEDecodeAudio`）、首尾帧
  输入、本地 ComfyUI 提交、候选进度、结果下载、Manifest、Job 和 Artifact 登记。
- GPU 服务器已连通，已完成 H3 在 3090 上的显存、速度与质量基准；第一集已用 H3
  跑通全 12 镜合成。
- 漫画动效 Profile 是可用降级路径，不冒充 AI I2V。
- 已新增无需 GPU 的配音时长规划：对白与语速决定目标镜头时长，长对白记录自然
  分段、建议镜头数和“需重生成/需拆镜”状态。
- 带声合成不再以冻结最后一帧作为主要补时方式；历史短片会将整段动作平滑铺满
  语音时间线，真实语音时长同时写回下一轮视频任务。
- 已新增逐镜头口型任务字段与界面：LatentSync 版本、目标人物、说话人跟踪及
  手动目标脸模式。模型推理仍待服务器或合适显存环境恢复后验证。
- 已新增本地生成模型中心，检测 GPU、显存、磁盘、模型文件、ComfyUI 节点与
  应用适配器；角色定妆支持在没有服务器密码时调用本机 ComfyUI。

## 2. 输入与输出

### 输入

- 已发布关键帧及其 RenderSpec。
- ShotPlan 中的动作、镜头运动、目标时长和首尾状态。
- 视频 Engine Profile。
- 可选尾帧、姿态、深度或运动参考。

### 输出

每个镜头输出：

- 标准代理视频，用于快速审片。
- 通过审核后的母版镜头视频。
- 技术元数据：编码、尺寸、帧率、时长和文件哈希。
- 生成元数据：模型、工作流、种子、参数、输入帧和任务日志。
- 质量报告与审核状态。

## 3. 视频 RenderSpec

在图片 RenderSpec 基础上增加：

- `subject_motion`：人物动作、速度和强度。
- `camera_motion`：推拉摇移、幅度、方向和稳定性。
- `temporal_constraints`：需保持不变的身份、服装、背景和道具。
- `duration_seconds`、`fps`、`frame_count`。
- `start_state`、`end_state`。
- `loop` 或转场需求。

动作描述必须简洁且可视化。一个短镜头不要同时要求多个复杂动作、运镜和场景变化。

## 4. 镜头复杂度策略

### 低风险

- 轻微呼吸、眨眼、头发衣摆。
- 缓慢推近、轻微摇镜。
- 背景氛围变化。

### 中风险

- 行走、转身、拿起物品、两人轻互动。
- 中等幅度运镜或局部特效。

### 高风险

- 多人高速战斗、复杂手部接触、快速形变。
- 大幅镜头运动叠加主体高速运动。
- 长时间口型与精确对白同步。

高风险镜头优先拆短、减少同屏人物，或采用漫画式推拉、遮罩、特效和剪辑替代。

## 5. I2V Adapter

统一接口至少包括：

- 环境与模型健康检查。
- Profile 能力查询。
- 任务提交、进度、取消、历史查询和恢复。
- 输入图/尾帧/控制条件上传。
- 输出下载与技术校验。
- 错误分类、显存恢复和受控降级。

如果通过 ComfyUI 执行 I2V，可复用第七阶段传输层，但视频请求、状态和质量报告应保持独立。

## 6. 后处理

模型原始输出进入剪辑前统一处理：

- 标准化分辨率、像素格式、帧率和编码。
- 按 ShotPlan 精确裁切时长。
- 可选补帧、轻度防抖和无损/高质量转码。
- 保留原始输出，后处理产生新 Artifact。
- 不通过强降噪或锐化掩盖严重身份漂移。

最终剪辑建议使用统一中间规格，避免不同模型输出导致 FFmpeg 拼接不稳定。

## 7. 质量检查

### 技术检查

- 文件可解码、无截断。
- 分辨率、帧率、时长和编码满足 Profile。
- 无大段黑帧、冻结帧或时间戳异常。

### 时序内容检查

- 人脸/主体身份随时间是否明显漂移。
- 背景、服装、道具是否突然变形或消失。
- 动作方向是否符合分镜。
- 镜头运动是否过强、抖动或与主体运动冲突。
- 首帧是否接近发布关键帧，尾帧是否利于下个镜头连接。

自动检查用于筛选和预警，关键镜头必须人工审看。

## 8. 音画时长协调

有对白的镜头在生成前读取预估配音时长：

- 配音短于镜头：允许反应、停顿或环境镜头。
- 配音略长：优先调整语速或镜头时长。
- 配音显著超长：回到导演阶段拆镜或缩短对白。

V1 不把精确口型同步作为硬门槛，但对白镜头需要避免持续清晰特写嘴部却完全不匹配。

## 9. 实施任务

1. 定义 VideoRenderSpec、VideoProfile、VideoArtifact 和 TemporalQualityReport。
2. 对候选 I2V 引擎做 3090 基准：显存、速度、质量、最大尺寸/时长。
3. 选定 V1 默认 Profile 并实现 Adapter。
4. 实现视频任务队列、恢复、缓存、版本和产物登记。
5. 实现 FFmpeg 标准化、探测、裁切和代理文件。
6. 实现技术检查、冻结帧/黑帧检测和基础时序偏差预警。
7. 建立不同复杂度镜头的降级规则。
8. 先验证 10 个代表性镜头，再完成 100 镜头稳定性测试。
9. 记录秒/帧、单镜头耗时、峰值显存和人工采用率。

## 10. 交付物

- 至少一个本地 I2V Adapter 与稳定 Profile。
- 视频生成、恢复、后处理和产物登记流程。
- 技术与时序质量报告。
- 10 镜头质量基准和 100 镜头稳定性报告。

## 11. Definition of Done

- [ ] 已发布关键帧可生成标准化镜头视频。
- [ ] 任务可暂停/取消/恢复，不会因断线重复生成。
- [ ] 每个视频能追溯到输入帧、模型、工作流和参数。
- [ ] 100 个镜头均有成功结果或明确的人工/降级处理结论。
- [ ] 无损坏文件、非法时间戳和无法拼接的编码差异。
- [ ] 核心人物镜头通过人工时序一致性审核。
- [ ] 高风险镜头的拆镜或漫画式降级流程实际可用。

## 12. 风险与退出条件

- 如果单镜头生成时间使整集成本不可接受，应降低分辨率、缩短镜头或采用静态漫画式动效。
- 如果身份时序漂移严重，不能只增加重试次数，应回到镜头复杂度、关键帧和视频控制条件。
- 具体模型和节点更新频繁，生产版本必须锁定，升级需跑固定基准集。
