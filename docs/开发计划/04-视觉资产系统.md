# 阶段 04：视觉资产系统

## 1. 阶段目标

建立可复用、可版本化的视觉资产库，为后续镜头提供稳定的人物身份、服装、场景、道具和整体美术风格。资产系统的核心不是“多生成图片”，而是建立可控的一致性锚点。

## 2. 资产范围

- 项目级 Art Bible：画风、线条、色彩、光影、构图、画幅和禁用元素。
- 人物：标准立绘、头像、三视图、表情、服装、年龄/阶段状态。
- 场景：建立镜头、日夜、天气、内外景和关键区域。
- 道具：武器、法器、徽记、载具和剧情关键物。
- 风格参考：经审核的样图、调色参考和渲染参数。

V1 不要求先训练 LoRA。先用稳定参考图、IP-Adapter/ControlNet 类条件控制和固定工作流验证一致性；只有参考控制仍不足时才进入轻量训练。

## 3. 前置输入

- 第三阶段发布的世界快照。
- 人物、地点、道具的稳定实体 ID。
- 人物在目标剧情时间点的外观与状态。
- 用户确认的美术方向和内容安全规则。

资产生成不能直接消费未经审核的别名字符串，所有绑定都使用实体 ID。

## 4. 资产数据契约

建议资产记录包含：

```json
{
  "schema_version": "1.0",
  "asset_id": "asset_char_xxx_v001",
  "entity_id": "char_xxx",
  "asset_type": "character_turnaround",
  "status": "approved",
  "version": 1,
  "files": [],
  "visual_spec": {},
  "generation": {
    "engine": "comfyui",
    "workflow_version": "",
    "model": "",
    "seed": 0,
    "prompt_hash": "",
    "input_assets": []
  },
  "review": {}
}
```

`visual_spec` 与具体生成引擎解耦。例如人物包含稳定特征、可变化特征、服装版本、配色和禁止偏移项。镜头阶段引用“人物 + 时间状态 + 服装版本”，而不是随意重新描述。

## 5. 资产生产流程

### 5.1 美术定向

1. 从少量主要人物和核心场景制作 2–3 套风格探索。
2. 确认画幅、线稿密度、色彩、材质和成人/暴力内容边界。
3. 选定一套 Art Bible，并冻结为版本。
4. 风格变化创建新版本，不覆盖旧剧集依赖。

### 5.2 人物资产

1. 根据世界事实生成结构化人物视觉规格。
2. 人工确认不可变身份特征。
3. 生成候选标准立绘并选定身份锚点。
4. 以锚点生成三视图、头像、表情和动作参考。
5. 为不同剧情阶段创建服装/伤势/年龄版本。
6. 通过审核后发布，后续镜头只能引用已发布版本。

### 5.3 场景与道具

- 先生成建立镜头，固定空间布局、材质、标志物和色彩。
- 日夜、天气和破坏状态作为同一场景的变体。
- 关键道具保留正侧背或足以维持形态的参考。

### 5.4 一致性策略

优先级：

1. 审核过的参考资产。
2. 固定基础模型、VAE、工作流和风格参数。
3. 稳定种子和结构控制。
4. 身份/风格参考适配器。
5. 必要时训练角色或风格 LoRA。

不得只靠在 Prompt 中重复人物名字来保证身份一致。

## 6. ComfyUI 工作流管理

- 工作流 JSON 放在 `workflows/`，使用语义版本。
- 业务代码通过命名参数填充工作流，不依赖易变化的节点序号。
- 启动时验证所需节点、模型和输入槽位。
- 保存执行后的完整工作流快照。
- 为 RTX 3090 GPU 服务器定义正式生产 Profile；可另设开发机低显存预览 Profile。OOM 时可降分辨率或分块，但必须显式记录降级。

## 7. 质量检查

自动检查：

- 文件可读、尺寸、透明通道和色彩模式。
- 重复图、明显纯色、黑图、损坏图。
- 人脸数量、主体缺失、参考相似度和越界裁切。
- 禁用元素和基本内容安全。

人工检查：

- 身份、年龄、发型、服装、武器和身体结构。
- 场景布局、时代感、世界观和风格一致性。
- 资产是否足以支持目标镜头角度。

一致率需要用固定角色、固定角度集进行评估，不能只随机挑选最好看的结果。

## 8. 实施任务

1. 定义 Art Bible、VisualSpec、Asset、AssetVersion 和 Review Schema。
2. 建立资产目录、登记表、版本、依赖和发布流程。
3. 实现 ComfyUI Adapter、工作流参数映射和环境预检。
4. 创建人物探索、人物参考、场景和道具的基础工作流。
5. 实现候选批次、缩略图、评分、人工选定和发布。
6. 实现资产失效传播：更换身份锚点时标记相关镜头为过期。
7. 增加基础自动质量检查和对比视图数据接口。
8. 建立 5 个角色、3 个核心场景、3 个关键道具的基准资产集。
9. 测量不同工作流的显存、耗时和成功率。

## 9. 交付物

- 版本化 Art Bible。
- 人物、场景和道具 VisualSpec。
- ComfyUI 适配器与基础工作流。
- 资产注册、审核、发布和追溯机制。
- 一致性评估集与基准报告。

## 10. Definition of Done

- [ ] 主要人物均有审核通过的身份锚点和最小参考集。
- [ ] 核心场景有建立镜头及必要的时间/天气变体。
- [ ] 所有资产可追溯到实体、Prompt、模型、工作流和随机种子。
- [ ] 失败可重试，已成功候选不会丢失或重复登记。
- [ ] 固定测试集的人物身份一致性目标 ≥95%。
- [ ] 3090 标准 Profile 可连续生成 20 个资产任务，无未处理 OOM。
- [ ] 下游可按稳定 ID 锁定已发布资产版本。

## 11. 风险与退出条件

- 若主要人物身份无法稳定，不进入长镜头批量生成。
- 若风格尚未冻结，不制作大量场景和道具变体。
- LoRA 训练会扩大数据、时间和许可风险，只在量化测试证明必要后加入。
