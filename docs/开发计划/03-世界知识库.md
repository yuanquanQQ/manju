# 阶段 03：世界知识库

## 1. 阶段目标

把第二阶段的结构化事实组织为可快速查询、可引用证据、可重建时间状态的世界知识库，为导演、资产生成和人工审核提供统一上下文。

知识库不是另一次小说解析。它只索引经过版本管理的事实与原文片段，并明确回答来自哪一章、哪段证据、哪个数据版本。

## 2. 设计原则

- SQLite 是事实源；JSON 是发布快照；搜索索引可随时重建。
- 精确结构化查询优先，全文和向量检索作为补充。
- 检索结果必须携带章节和证据定位。
- 不把 FAISS 当数据库，不在索引中保存唯一副本。
- 向量模型或分块策略变化时创建新索引版本，不原地混用。
- 世界状态按时间点查询，不能只返回人物“当前最终状态”。

## 3. 查询类型

### 结构化查询

- 某人物在哪些章节出现？
- 某事件有哪些参与者、发生在哪里？
- 某人物在第 50 章时属于什么阵营、具有什么能力？
- 两个人物的关系何时发生变化？

### 全文查询

- 查找明确名称、台词、招式或物品原文。
- 支持 SQLite FTS5 与中文分词策略。

### 语义查询

- “主角第一次获得异火是什么时候？”
- “哪些事件让两位角色从敌对转为合作？”
- “这一幕之前观众需要知道哪些背景？”

语义查询由向量召回候选，结合元数据过滤和可选重排，最终返回证据而非无来源答案。

## 4. 数据组织

### 事实层

- `entities`：稳定实体。
- `entity_aliases`：别名及证据。
- `mentions`：实体在原文中的出现。
- `events`：事件、顺序、因果和重要度。
- `relations`：关系及有效时间。
- `state_changes`：属性变化。
- `dialogues`：对白和说话人。
- `evidence_spans`：原文定位。

### 检索层

- `knowledge_chunks`：用于检索的最小语义单元。
- `fts_index`：名称、摘要、事件、对白等关键词索引。
- `vector_index_manifest`：嵌入模型、维度、分块版本和文件哈希。
- FAISS 索引文件：只保存向量 ID，元数据仍回查 SQLite。

### 快照层

输出建议：

```text
snapshots/{snapshot_id}/
├─ manifest.json
├─ world.json
├─ characters.json
├─ locations.json
├─ organizations.json
├─ props.json
└─ timeline.json
```

快照是某一审核版本的只读发布物，供下游阶段固定引用。

## 5. 检索流程

```text
用户/Agent 查询
  → 意图识别与实体解析
  → 结构化过滤
  → FTS5 关键词召回 + 向量召回
  → 合并去重
  → 可选重排
  → 返回事实、时间点、证据和置信度
```

返回对象至少包括：

- `answer_facts`：可直接使用的结构化事实。
- `evidence`：章节、起止位置、短引用。
- `entities`：命中的稳定实体 ID。
- `retrieval_score`：仅用于排序，不冒充事实置信度。
- `snapshot_id` 和 `index_version`。

生成自然语言答案是可选展示层；导演等下游组件优先消费结构化结果。

## 6. 索引生命周期

1. 对已审核或允许使用的事实生成知识块。
2. 计算 `chunk_hash`，只嵌入新增或变更内容。
3. 写入新索引临时文件。
4. 完成数量、维度、随机检索和文件哈希校验。
5. 原子切换活动索引 Manifest。
6. 保留上一版以便回滚。

删除或合并实体后，标记受影响块失效并重建；不要依赖向量库的隐式覆盖。

## 7. 实施任务

1. 定义知识块、检索请求、检索结果和快照 Schema。
2. 建立 FTS5 索引及适合中文的 token 化方案。
3. 接入本地 Embedding Adapter，记录模型和维度。
4. 实现增量 FAISS 构建、版本切换、验证与回滚。
5. 实现实体、时间、章节、事实类型和审核状态过滤。
6. 实现关键词与向量混合排序。
7. 实现世界状态重放与“截至某章”的查询。
8. 实现 JSON 快照导出、校验和下游锁定。
9. 增加 CLI：`kb build`、`kb query`、`kb verify`、`snapshot create`。
10. 建立检索评估问题集和性能报告。

## 8. 测试与评估

测试集至少包含：

- 明确关键词、别名、同名人物、模糊语义和否定问题。
- 首次出现、状态变化、因果链和跨章关系。
- 查询指定章节时间点，确保不会泄漏后续剧情。
- 索引中断、旧索引回滚、数据库变更后的增量重建。

核心指标：

- Recall@5、MRR 或命中前 5 的比例。
- 答案证据正确率。
- 时间点查询正确率。
- 1000 章规模的 P50/P95 查询耗时。
- 增量构建时间和索引大小。

## 9. 交付物

- 结构化查询服务。
- FTS5 与本地向量混合检索。
- 世界状态时间查询。
- 版本化 JSON 快照。
- CLI 与评估报告。

## 10. Definition of Done

- [ ] 人物、地点、事件、对白和状态变化均可查询。
- [ ] 每条结果能定位到原文章节与证据。
- [ ] 固定问题集 Top-5 命中率达到约定阈值，目标 ≥95%。
- [ ] 常见查询在本机 5 秒内完成，目标 P95 <2 秒。
- [ ] 指定章节查询不会使用该章之后的事实。
- [ ] 索引可增量更新、完整重建、验证和回滚。
- [ ] 可生成自洽且带 Manifest 的发布快照。

## 11. 风险与退出条件

- 若结果无法稳定引用原文，不向导演 Agent 开放自由问答。
- 若向量检索收益不明显，可先用结构化查询和 FTS5 完成 V1，FAISS 不作为硬依赖。
- 若世界状态冲突过多，必须回到第二阶段解决实体归一和事实版本问题。
