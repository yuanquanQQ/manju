# 阶段 07：图片生成

## 1. 阶段目标

通过 ComfyUI 批量执行 RenderSpec，为每个镜头生成可审核的关键帧，并确保任务可恢复、结果可追溯、失败可分类。阶段成功包含两个独立概念：

- 技术成功：请求完成并得到合法图片。
- 内容合格：图片通过自动检查和人工审核，可进入图生视频。

## 2. 生成策略

V1 推荐“候选 → 审核 → 发布”：

1. 每个镜头先生成少量低成本候选。
2. 自动过滤损坏和明显失败结果。
3. 人工选择最佳候选，必要时局部修改 Prompt 或种子重做。
4. 对选中候选生成目标分辨率版本。
5. 发布为镜头关键帧，锁定输入版本。

不要一开始为整集所有镜头生成大量高分辨率候选。

## 3. ComfyUI Adapter

适配器负责：

- 连接和健康检查。
- 校验工作流所需模型、自定义节点和输入文件。
- 上传或映射参考资产。
- 提交 Prompt、获取 `prompt_id`。
- 通过 WebSocket 监听进度，HTTP 轮询作为恢复手段。
- 下载、校验、重命名和登记结果。
- 取消队列/当前任务。
- 将 ComfyUI 错误转换为统一错误分类。

业务 Pipeline 不直接依赖 ComfyUI 节点编号和返回目录。

## 4. 任务模型

建议拆分：

- `ImageBatchJob`：场景或整集级队列。
- `ImageRenderJob`：一个镜头的一次候选批次。
- `ImageCandidate`：单张结果。
- `ImageReview`：接受、拒绝、评分和原因。
- `PublishedFrame`：下游锁定的关键帧版本。

每个候选保存：

- RenderSpec 和 EngineRequest 哈希。
- 模型、工作流、节点版本、采样参数和种子。
- 输入参考资产及权重。
- ComfyUI `prompt_id`、耗时、峰值显存和输出哈希。
- 自动检查、人工审核及失败原因。

## 5. 幂等与恢复

- 提交前检查缓存键；相同成功任务直接复用。
- ComfyUI 已接收但客户端断线时，先按 `prompt_id` 查询历史，不能立即重复提交。
- 下载使用临时文件，校验完成后原子移动。
- 进程启动时扫描 `RUNNING` 任务并与 ComfyUI 队列/历史对账。
- 已发布关键帧不会被普通重跑覆盖；重做产生新版本。

## 6. 自动质量检查

### 技术检查

- 文件存在且可解码。
- 尺寸、画幅、颜色模式和最小文件大小正确。
- 无纯黑、纯白、明显截断或损坏。
- 输出数量与请求一致。

### 内容辅助检查

- 预期主体/人脸数量。
- 角色身份参考相似度。
- 明显多肢体、重复人物、错误裁切等异常分数。
- 与相邻镜头的色彩、场景和人物参考偏差。

自动内容检查只做排序和预警。没有经过验证的阈值，不应自动删除候选。

## 7. 重试与降级

按错误原因处理：

- 连接/超时：退避重连，先查询历史。
- 模型或节点缺失：立即阻断，不重试。
- OOM：清理显存后重试；仍失败则切换低显存 Profile，并明确记录降级。
- 内容不合格：改变种子或受控参数，不使用完全相同请求重试。
- 持续身份偏移：回到资产/Prompt 阶段，不无限抽卡。

每类错误设置最大次数和冷却时间，避免 GPU 死循环。

## 8. 文件组织

```text
production/shots/{shot_id}/images/
├─ manifest.json
├─ candidates/
│  ├─ v001_c001.png
│  └─ v001_c002.png
├─ previews/
├─ rejected/
└─ published/
   └─ frame_v001.png
```

数据库保存相对路径，文件名不承担全部元数据。

## 9. 实施任务

1. 完成 ComfyUI 连接、预检、提交、进度、历史、取消和下载适配器。
2. 定义图片任务、候选、审核、发布和质量报告 Schema。
3. 实现缓存键、对账、恢复、原子下载和产物登记。
4. 实现技术检查和可插拔内容质量检查。
5. 实现按错误类别的重试、OOM 恢复和 Profile 降级。
6. 实现单镜头/单场景/整集队列及优先级。
7. 实现缩略图和联系表产物，供 GUI 审核。
8. 先完成 10 镜头试跑，再进行 100 镜头稳定性测试。
9. 记录速度、显存、失败和候选采用率。

## 10. 测试与验收

- 模拟 ComfyUI 不在线、执行中断、历史可查、下载损坏和节点缺失。
- 模拟进程在提交后、生成中和下载中退出，重启后均可恢复。
- 同一请求重复执行只登记一个有效任务，除非显式要求新候选。
- 100 镜头测试应覆盖单人、双人、场景、动作和特效。

## 11. 交付物

- 稳定的 ComfyUI Adapter。
- 图片任务队列、恢复和产物登记。
- 候选审核、发布和版本机制。
- 自动质量检查与 100 镜头基准报告。

## 12. Definition of Done

- [ ] 单镜头可提交、查看进度、取消、恢复和重试。
- [ ] 所有候选可追溯到完整生成参数和输入资产。
- [ ] 100 镜头批处理技术成功率 ≥98%，失败均有明确原因。
- [ ] 技术成功与内容通过率分别统计。
- [ ] 已发布关键帧只有显式操作才能被新版本替代。
- [ ] 断开客户端或重启应用不会无意重复 GPU 任务。
- [ ] RTX 3090 连续运行无未处理 OOM，磁盘增长可监控。

## 13. 风险与退出条件

- 技术成功率达标但内容采用率很低时，停止扩量，回到资产和 Prompt。
- 磁盘可能比显存更早成为瓶颈，必须先实现缓存与候选清理策略。
- 自定义节点版本变化会破坏工作流，生产 Profile 必须锁定并可诊断。
