# 阶段 01：项目基础与工程规范

## 1. 阶段目标

建立后续九个阶段共同依赖的工程底座：配置、项目结构、数据迁移、任务状态、日志、测试和 CLI。完成后，即使具体 AI 能力尚未实现，系统也能稳定创建项目、登记任务、恢复状态并验证环境。

## 2. 当前基线

已有：

- `main.py` 提供 `create`、`ingest`、`info` 命令。
- `app/core` 提供环境配置和日志。
- `app/database` 提供 SQLite 与 SQLAlchemy 模型。
- `app/pipeline/ingest.py` 提供基础入库流程。
- 项目目录可创建 `novel`、`database`、`assets`、`outputs`、`chapters`。

仍需补齐：

- 依赖锁定、包元数据、数据库迁移、Schema 版本和任务表。
- 单元测试、集成测试、GPU/外部服务健康检查。
- 安全的项目名和路径校验、统一异常与退出码。
- 可取消、可暂停、可恢复的任务执行器。

## 3. 范围

### 本阶段包含

- Python 工程规范和模块边界。
- 全局配置、项目级配置和运行配置。
- 项目清单、目录约定、数据库初始化与迁移。
- Pipeline 的基础任务模型，不实现具体生成算法。
- CLI 基础命令、日志、诊断、测试与开发文档。

### 本阶段不包含

- 小说语义解析。
- 图片、视频、音频生成。
- 最终桌面 GUI。

├─ app/
│  ├─ core/             # 配置、错误、日志、ID、哈希
│  ├─ domain/           # Pydantic 领域 Schema
│  ├─ database/         # ORM、Repository、迁移
│  ├─ adapters/         # LLM、ComfyUI、I2V、TTS、FFmpeg

│  ├─ renderer/         # 图片/视频/合成
│  └─ gui/              # PySide6
├─ migrations/
├─ workflows/
├─ models/
├─ projects/
├─ tests/

业务模块之间通过 Domain Schema 和 Service 接口通信，避免互相导入 ORM 实例或具体适配器。

## 5. 项目目录契约

每个用户项目建议采用：

```text
projects/{project_id}/
├─ project.json             # 项目清单、schema_version、创建时间
├─ config.yaml              # 项目覆写配置，不含密钥
├─ novel/
│  ├─ source/               # 原始文件，只读
│  ├─ chapters/             # 标准化章节
│  └─ revisions/            # 人工修订
├─ database/world.db
├─ indexes/
├─ assets/
│  ├─ characters/
│  ├─ locations/
│  ├─ props/
│  └─ styles/
├─ production/
│  ├─ episodes/
│  ├─ shots/
│  └─ audio/
├─ cache/
├─ outputs/
└─ logs/
```

`project_id` 使用不可变 ID，显示名称可修改。创建项目时必须拒绝路径穿越字符，并保证目标位于 `projects/` 内。

## 6. 核心设计

### 配置层级

优先级：

```text
命令行参数 > 项目 config.yaml > 环境变量/.env > 全局默认值
```

配置按子系统分组：`llm`、`embedding`、`comfyui`、`video`、`tts`、`ffmpeg`、`storage`、`pipeline`。密钥只允许来自环境变量或系统凭据，不写入项目文件。

### 数据库迁移

- 使用 Alembic 或等价迁移机制。
- 新项目执行最新迁移；旧项目原地升级并先备份数据库。
- 每次迁移有 upgrade、downgrade 和最小验证用例。
- SQLite 启用外键约束，配置合理的 WAL 和 busy timeout。

### 任务与产物

最低数据表：

- `jobs`：类型、状态、优先级、进度、重试、错误、输入哈希。
- `job_dependencies`：任务依赖。
- `artifacts`：类型、路径、哈希、大小、创建任务、元数据。
- `reviews`：审核状态、意见、操作者和时间。
- `settings_snapshots`：运行时配置快照。

大文件不进入 SQLite，只保存相对项目根目录的路径和校验信息。

### 错误分类

- `ValidationError`：输入或 Schema 不合法，不自动重试。
- `DependencyError`：服务、模型或文件缺失，等待环境恢复。
- `ResourceError`：显存、内存或磁盘不足，可降级或暂停。
- `TransientError`：超时、连接中断，可退避重试。
- `ContentQualityError`：生成完成但未通过质量门槛，需要重生成或人工处理。

## 7. 实施任务

1. 建立 `pyproject.toml`，明确 Python 3.11，选择并固定一种依赖管理方式。
2. 增加代码格式、静态检查和测试配置。
3. 定义项目清单、配置和任务相关 Pydantic Schema。
4. 重构配置字段，统一新命名并提供旧配置迁移提示。
5. 建立 Repository 与事务边界，避免 Pipeline 直接散落 ORM 查询。
6. 引入数据库迁移并为现有 `world.db` 提供基线迁移。
7. 实现任务状态机、心跳、取消令牌、重试策略和进度事件。
8. 实现原子文件写入、内容哈希、磁盘空间检查和缓存目录管理。
9. 扩展 CLI：`create`、`doctor`、`status`、`run`、`resume`、`cancel`、`clean-cache`。
10. 编写 Windows/RTX 3090 环境诊断和基础开发指南。

## 8. 测试计划

- 创建合法项目、重复创建、非法名称、超长路径。
- 配置优先级、错误类型、缺失配置和旧变量兼容。
- 全新数据库初始化、旧库迁移、迁移失败恢复。
- 任务成功、失败、重试、暂停、恢复、取消和上游失效传播。
- 原子写入中断后不留下被当成成功结果的半文件。
- Windows 路径、中文文件名和 UTF-8 编码。
- `doctor` 能检测 Python、SQLite、FFmpeg、GPU 和配置的服务端点。

- `pyproject.toml` 和锁文件。

## 10. Definition of Done

- [x] 新环境可以按文档安装并运行 `python main.py --help`。
- [x] `create` 可安全创建项目并生成带版本的项目清单。
- [x] 数据库可初始化、迁移、备份和恢复。
- [x] 示例任务可暂停、恢复、取消，进程崩溃后可识别并恢复。
- [x] 相同输入重复运行不会产生重复任务/产物。
- [x] 自动测试覆盖核心配置、路径、数据库和任务状态机。
- [x] 日志能通过 `project_id`、`job_id` 追踪一次运行。

## 11. 风险与退出条件

- 如果基础任务模型仍频繁修改，不进入大规模小说解析。
- 如果迁移无法保护现有项目数据，先做只读导出/重建工具。
- 如果当前原型与目标架构冲突，优先保留数据，允许分步重构代码。
