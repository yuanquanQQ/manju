# 阶段 02：小说编译器

## 1. 阶段目标

把原始小说编译成可验证、可追溯、可增量更新的结构化叙事数据。小说编译器是后续知识库、资产、导演和配音的事实来源，必须优先保证证据、稳定 ID 和可修订性，而不是追求一次抽取出尽可能多的字段。

## 2. 当前基线与关键问题

当前实现可扫描章节 JSON、调用 OpenAI 兼容本地 LLM、解析基础 JSON，并写入 `chapters`、`characters`、`scenes`、`events` 等表。

需要修正的关键问题：

- Prompt 要求模型判断“本章首次出现”，但调用时没有提供已知人物/场景状态，结果不可可靠判断。
- 只保留“新人物/新场景”，会丢失后续出场时的服装、关系、状态和别名变化。
- 章节正文按字符截断可能丢失结尾事件。
- 输出缺少 Pydantic 强校验、证据区间、置信度、模型与 Prompt 版本。
- 人名按字符串唯一会把别名拆成人，也可能把同名人物错误合并。
- `--force` 与补库路径必须验证幂等，防止事件重复。

新版流程把“章节事实抽取”和“跨章实体归一/判新”分成两个明确步骤。

## 3. 输入与输出

### 支持输入

- 单个 TXT/Markdown 长文。
- 多文件章节 TXT/Markdown。
- 已切分的章节 JSON。

所有输入先转为不可变的标准章节：

```json
{
  "schema_version": "1.0",
  "chapter_id": "ch_000001",
  "order": 1,
  "title": "第一章",
  "content": "...",
  "source_file": "novel/source/book.txt",
  "source_start": 0,
  "source_end": 5321,
  "content_hash": "sha256:..."
}
```

### 核心输出

- 人物提及、别名、外观、能力、阵营和状态变化。
- 地点/场景提及、层级、时间、天气和视觉特征。
- 道具、功法、组织与其他可复用实体。
- 事件、参与者、因果、时间顺序、重要度和剧情功能。
- 对白、说话人、语气以及原文位置。
- 章节摘要、悬念、冲突、情绪曲线和适配提示。
- 所有事实的原文证据与置信度。

## 4. 数据契约

建议的 `ChapterAnalysis` 顶层：

```json
{
  "schema_version": "1.0",
  "chapter_id": "ch_000001",
  "mentions": [],
  "events": [],
  "dialogues": [],
  "state_changes": [],
  "summary": "",
  "adaptation_notes": [],
  "warnings": [],
  "provenance": {
    "model": "",
    "prompt_version": "",
    "input_hash": ""
  }
}
```

每条事实至少带：

- `fact_id`：稳定 ID。
- `surface_text`：原文中的称呼。
- `entity_type`：character/location/organization/prop/ability。
- `evidence`：章节、起止位置、短引用。
- `confidence`：0–1。
- `review_status`：unreviewed/approved/rejected/edited。

事件至少包含参与者、地点、顺序、因果、重要度、结果和状态变化。所有枚举和值域由 Pydantic/JSON Schema 限制。

## 5. 编译流水线

### 5.1 导入与章节切分

1. 检测 UTF-8、GB18030 等常见编码，保存检测结果。
2. 标准化换行和不可见字符，不擅自改写正文。
3. 使用章节标题规则切分，并允许用户预览、合并或拆分。
4. 保存原文件偏移和内容哈希。
5. 重复导入相同内容时复用结果。

### 5.2 分块分析

- 长章节按自然段和语义边界切块，块之间保留少量重叠。
- 每块先抽取局部事实，章节级步骤再合并、去重和排序。
- 不用截断代替分块。
- 每块失败只重试该块。

### 5.3 章节事实抽取

模型只回答“本章出现了什么”，不负责判断全书首次出现。使用结构化输出、低随机性、严格 Schema 验证；验证失败时进行有限次数的修复调用，最终失败进入人工队列，不能静默返回空结果并标记成功。

### 5.4 实体解析

1. 从提及中生成候选实体。
2. 使用规范化名称、别名、共现、描述和上下文检索候选。
3. 高置信度自动合并，中等置信度进入审核，低置信度新建实体。
4. “首次出现章节”由已归一实体的最早证据计算，不由模型直接声明。
5. 合并/拆分实体必须保留历史并重定向引用。

### 5.5 世界状态归并

按章节顺序应用状态变化，形成可重建的时间线。冲突事实不直接覆盖：保存多版本、证据和冲突标记，等待规则或人工解决。

## 6. 人工审核

审核界面至少支持：

- 查看结构化事实旁边的原文证据。
- 修改说话人、人物别名、地点和事件边界。
- 合并/拆分实体。
- 标记事实错误或不确定。
- 锁定人工结果，防止重跑被覆盖。

人工编辑作为 Patch 层保存，重新抽取时先生成新机器版本，再重新应用仍有效的 Patch。

## 7. 实施任务

1. 定义标准章节、证据、实体提及、事件、对白和状态变化 Schema。
2. 实现 TXT/Markdown/JSON 导入与可预览章节切分。
3. 将现有字符截断改为可恢复的分块分析。
4. 把 LLM 调用封装到统一适配器，记录用量、耗时和版本。
5. 引入严格输出验证、错误分类、修复与失败队列。
6. 新建实体、别名、提及、证据、关系、状态变化和版本表。
7. 实现实体候选检索、自动归一和人工审核队列。
8. 实现章节增量更新和下游失效传播。
9. 为现有章节 JSON 编写一次性迁移/导入工具。
10. 建立带人工真值的评估集和回归报告。

## 8. 评估方案

固定选择至少 50 章，覆盖开篇、对话密集、战斗、转场、回忆和多角色章节，由人工制作真值。

指标分开计算：

- 章节切分准确率。
- 人物/地点/道具提及 Precision、Recall、F1。
- 实体归一准确率与错误合并率。
- 事件参与者、地点和顺序准确率。
- 对白说话人准确率。
- 摘要事实一致性。
- 结构化输出成功率、平均重试次数和单章耗时。

“准确率 ≥90%”必须明确指标和样本，不能只凭主观抽查得出。

## 9. 交付物

- 原始小说导入器与章节切分器。
- 版本化的小说分析 Schema 和数据库迁移。
- 分块抽取、合并、实体归一和世界状态归并流程。
- 人工审核数据接口。
- 评估集、评估脚本与基准报告。
- 可继续运行、可重跑、可迁移的现有项目数据。

## 10. Definition of Done

- [x] TXT、Markdown 和章节 JSON 均可导入并定位回原文。
- [ ] 100 章连续解析中断后可恢复，不产生重复事实。
- [x] 结构化结果全部通过版本化 Schema 校验。
- [x] 人物、地点和事件均带原文证据。
- [ ] 别名可合并，同名冲突可进入人工审核。
- [x] 失败章节不会被空结果伪装成成功。
- [ ] 固定评估集的核心指标达到约定阈值，关键事实综合准确率 ≥90%。
- [x] 章节内容未变化时复用成功结果，变化时生成新分析版本。

## 11. 风险与退出条件

- 若实体错误合并率不可接受，不进入自动资产绑定。
- 若事件和对白缺少可靠证据，不进入导演与配音阶段。
- 如果本地模型无法稳定满足 Schema，先缩小任务、分两次抽取或升级适配器，不在后处理里无限容错。
